# 01：笔记标题连续词命中的端到端拒绝与提示

> 已发布：[GitHub Issue #3](https://github.com/wxb-gs/live_community/issues/3)。父规格：[#2](https://github.com/wxb-gs/live_community/issues/2)。标签：ready-for-agent。发布日期：2026-10-25。尚未开始实现。

## What to build

让作者仍能保存草稿，但发布服务端草稿标题命中明确测试词条时，笔记不会公开；发布页面保留输入，并在标题下方的错误预览中高亮原文命中片段。此任务同时打通必要的结构化错误返回和前端消费路径，作为后续场景复用的最小完整链路。

## Acceptance criteria

- [ ] 先兼容扩展现有错误响应及请求封装，再接入标题检查；未使用新错误类型的调用方仍正常工作，原有认证失效和限流处理保持有效。
- [ ] 检测能力归属 note-service 应用层；使用显式提供的词表，HTTP 与 Dubbo 发布都经过同一检查，不将网关或前端预检作为权威检查。
- [ ] 第一条可演示链路覆盖中文、英文连续子串命中。词条 bad 出现在 bad、badminton、bad123 或 _bad_ 中均拒绝；大小写和全角变形由 04 补充。
- [ ] 检查服务端实际草稿标题，保留现有身份、作者和状态校验；无权调用者不能通过错误详情获得内容或检测信息。
- [ ] 命中时不发生本次公开状态变更或新增发布投影；草稿仍保留。已有草稿的非公开 Outbox 记录不被错误视为本次发布造成的副作用。
- [ ] 正常标题仍能完成既有发布流程，草稿保存不被敏感词发布规则拒绝。
- [ ] 错误详情包含字段及原文命中区间等高亮所需信息；页面使用现有输入框下方的安全文本预览，不替换原文，不引入富文本编辑器。
- [ ] 一次最多展示 20 处命中，超过时提示还有更多；展示上限不能导致含有命中的输入被放行。不向调用方返回完整词表。
- [ ] 以真实检测能力和固定测试词表通过发布应用入口验证成功、拒绝和持久化状态；补最小 HTTP 错误契约及发布页面交互验收，不断言私有扫描实现。
- [ ] 不选择生产词库文件、数据库、配置中心或管理后台，也不新增独立过滤服务；不得声称真实生产词库已接入。
