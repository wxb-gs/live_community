# 05：所有公开提交的检测故障拦截与重试提示

> 已发布：[GitHub Issue #7](https://github.com/wxb-gs/live_community/issues/7)。父规格：[#2](https://github.com/wxb-gs/live_community/issues/2)。标签：ready-for-agent。发布日期：2026-10-25。尚未开始实现。

## What to build

当检测能力发生可控异常时，笔记发布、根评论和回复都不会绕过检查公开内容。用户看到的是检测暂时不可用、可以稍后重试，而不是被错误指责含有敏感词；输入和已有草稿保持可恢复。

## Acceptance criteria

- [ ] 为检测故障提供与词条命中可区分的错误类型；不擅自把尚未约定的具体 HTTP 状态或业务码说成用户已选定的值。
- [ ] 笔记标题或正文检测故障均阻止本次发布，保留已有草稿，不新增本次公开状态或发布投影。
- [ ] 根评论或回复检测故障均阻止本次可见写入，评论索引、正文及主题计数不出现部分变化。
- [ ] HTTP 和内部 Dubbo 调用遵循同样的故障阻断行为；不增加默认放行的降级分支。
- [ ] 发布、评论和回复界面明确显示可重试故障提示，保留输入；回复保留回复目标。故障不展示伪造的命中词或高亮区间。
- [ ] 检测恢复后，相同内容可以按正常检测结果重新提交；成功流程能退出提交中状态并正常刷新。
- [ ] 对可控故障进行注入，通过应用入口和真实持久化结果验证阻断，再补必要传输及界面验收；正常和命中路径仍使用真实检测组件与固定词表。
- [ ] 确认认证失效、业务无权限和入口限流等既有错误没有被误分类为检测故障。
- [ ] 不借故障处理新增词库热更新、运营管理、历史重审或独立审核微服务；测试供给故障不等同于选择生产词库供给方案。
