# 评论区功能（MySQL 重构版）

> 本文含历史设计。当前实现以 [微服务修复实施与部署](../微服务修复实施与部署.md) 为准：HTTP 网关、内部 Dubbo、上传确认后发布、MySQL 权威互动与 Outbox。

> **2026-06-23 重构**：从 Cassandra 迁移至 MySQL，采用索引/内容分离 + 根路径扁平化架构。
> 详见 `docs/feature/04-笔记与评论功能（Cassandra）.md` 了解旧版 Cassandra 设计。

## 1. 功能概述

评论区功能包含四个核心能力：**发表评论**、**嵌套回复（盖楼）**、**评论列表展示**、**评论点赞**。

```
┌──────────────────────────────────────────────────────────────┐
│                     评论区功能                                │
├──────────────────────────────────────────────────────────────┤
│ POST /api/note/comment      → 发表评论/回复（Leaf 生成 ID）    │
│ GET  /api/note/comments     → 分页拉取根评论（含子回复预览）    │
│ GET  /api/note/replies      → 分页拉取子回复列表               │
│ GET  /api/note/detail       → 笔记详情含首页评论               │
│ POST /api/interaction/toggle → 评论点赞/取消（Redis+Kafka）    │
└──────────────────────────────────────────────────────────────┘
```

评论数据全部存储在 Cassandra，ID 由 Leaf 号段模式生成，点赞使用 Cassandra 原生 COUNTER 类型保证原子增减。

## 2. 数据模型（MySQL 三表分离）

### 设计思想：索引/内容分离 + 根路径扁平化

```
┌─────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ comment_subject │     │  comment_index   │     │ comment_content  │
│   (计数与状态)   │     │  (关系与排序)     │     │   (文本内容)      │
│                 │     │                  │     │                  │
│ obj_id          │     │ id (Leaf生成)     │     │ comment_id       │
│ obj_type        │     │ obj_id           │     │ message (TEXT)    │
│ count           │     │ obj_type         │     │ extra            │
│ root_count      │     │ root_id          │     └──────────────────┘
│ state           │     │ parent_id        │
└─────────────────┘     │ user_id          │
                        │ like_count       │
                        │ floor            │
                        │ create_time      │
                        │ state            │
                        └──────────────────┘
```

### 2.1 评论主题表 `comment_subject`

```sql
CREATE TABLE comment_subject (
    obj_id     BIGINT  NOT NULL,
    obj_type   TINYINT NOT NULL,   -- 1:笔记
    count      INT     NOT NULL DEFAULT 0,
    root_count INT     NOT NULL DEFAULT 0,
    state      TINYINT NOT NULL DEFAULT 0,  -- 0:正常 1:禁止评论
    PRIMARY KEY (obj_id, obj_type)
);
```

### 2.2 评论索引表 `comment_index`

```sql
CREATE TABLE comment_index (
    id          BIGINT   NOT NULL,    -- Leaf 号段生成
    obj_id      BIGINT   NOT NULL,
    obj_type    TINYINT  NOT NULL DEFAULT 1,
    root_id     BIGINT   NOT NULL DEFAULT 0,   -- 0 = 根评论
    parent_id   BIGINT   NOT NULL DEFAULT 0,   -- 回复的父评论
    user_id     BIGINT   NOT NULL,
    like_count  INT      NOT NULL DEFAULT 0,   -- Redis 异步同步
    floor       INT      NOT NULL DEFAULT 0,
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
    update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
    state       TINYINT  NOT NULL DEFAULT 0,   -- 0:正常 1:隐藏 2:删除
    PRIMARY KEY (id),
    INDEX idx_obj_root (obj_id, obj_type, root_id, create_time),
    INDEX idx_root (root_id, create_time),
    INDEX idx_user (user_id, create_time)
);
```

**核心索引 `idx_obj_root`**：覆盖最高频的"拉取根评论列表"查询，包含 `obj_id + obj_type + root_id + create_time`，支持高效分页。

### 2.3 评论内容表 `comment_content`

```sql
CREATE TABLE comment_content (
    comment_id BIGINT       NOT NULL,
    message    MEDIUMTEXT   NULL,
    extra      VARCHAR(4096) NULL,
    PRIMARY KEY (comment_id)
);
```

**分离原因**：`comment_index` 是窄表，MySQL Buffer Pool 能缓存更多索引行，分页扫描效率远高于宽表。`comment_content` 仅在需要展示文本时才按主键查询。

## 3. API 端点

### 3.1 发表评论/回复

```
POST /api/note/comment
```

| 项 | 说明 |
|----|------|
| 认证 | 需要登录 |
| 请求体 | `{ "noteId": Long, "content": String, "parentId": Long, "rootId": Long }` |
| 响应体 | `Result<CommentResponse>` — 含 rootId, parentId, floor |

**调用链**：

```
Gateway → Dubbo → NoteService.addComment()
  → CommentService.addComment()
    → LeafRpcService.generateSegmentId("comment")
    → validate parent exists (if reply)
    → comment_index INSERT
    → comment_content INSERT
    → comment_subject count +1
    → 返回 CommentResponse
```

### 3.2 分页获取根评论列表

```
GET /api/note/comments?noteId=xxx&page=0&size=20
```

每页 20 条根评论，每条附带前 3 条子回复预览（`previewReplies`）+ 回复总数（`replyCount`）。查询路径：

1. `idx_obj_root` 索引 → 根评论分页（`root_id = 0`）
2. 批量 `IN` 查询 `comment_content` 获取文本
3. 每条根评论查前 3 条子回复（`idx_root` 索引）
4. 统计每条根评论的回复总数

### 3.3 分页获取子回复

```
GET /api/note/replies?rootId=xxx&page=0&size=20
```

按创建时间升序拉取某根评论下的所有子回复。

### 3.4 笔记详情（含评论）

```
GET /api/note/detail?noteId=xxx
```

返回第一页根评论（含子回复预览），更多评论通过 `/api/note/comments` 分页加载。

### 3.5 评论点赞

```
POST /api/interaction/toggle
{ "interactionType": "LIKE", "targetType": "comment", "targetId": Long }
```

**实现路径（与笔记点赞统一）**：

```
Redis + Lua 原子 toggle（实时）
  → Kafka 事件
    → InteractionEventConsumer（30s 窗口聚合）
      → comment_index.like_count +1/-1（批量同步）
```

不经过 Cassandra，评论点赞与笔记点赞使用同一套 Redis + Kafka → MySQL 异步链路。

## 4. 嵌套回复（盖楼）方案

采用"根路径 + 扁平化"设计：

- 数据库只存 `root_id` + `parent_id`，不存完整路径
- `root_id = 0` 表示根评论，`root_id > 0` 表示属于哪个根评论的子树
- 前端/后端按 `root_id` 聚合子树，转为树状结构展示
- 默认折叠：只展示前 3 条子回复预览，点击"加载更多"分页拉取完整回复列表

**为什么不递归查询？** MySQL 递归 CTE 在大数据量下性能不可控。按 `root_id` + `create_time` 索引拉平所有回复后，由应用层组装树，效率高且可控。

## 5. 性能优化要点

| 策略 | 说明 |
|------|------|
| **索引/内容分离** | 窄表 `comment_index` 分页扫描效率远高于宽表 |
| **复合索引覆盖查询** | `idx_obj_root` 覆盖根评论分页，`idx_root` 覆盖回复分页 |
| **游标分页** | 使用 `LIMIT/OFFSET`（可通过 `WHERE id > lastId` 演进） |
| **Redis 挡热点** | 点赞计数在 Redis 实时更新，异步 30s 批量刷 MySQL |
| **冷热分离** | 旧评论可归档到历史表，热评论保持在主表 |
| **分片键** | 按 `obj_id` 分片，同一对象的所有评论落在同一分片 |

## 6. 前端实现

### 6.1 CommentInput — 评论输入框

支持两种模式：
- **根评论模式**：底部输入框，占位符 "说点什么..."
- **回复模式**：显示"回复 @用户名"标签，可取消

### 6.2 CommentItem — 评论展示 + 嵌套回复

- 根评论：显示楼层号 + 回复按钮
- 子回复：左侧缩进 + 灰色竖线视觉层级
- 前 3 条子回复预览自动展示
- "展开更多回复" 按钮分页加载完整回复列表
- 点赞去抖 + 乐观更新

### 6.3 TypeScript 类型

```typescript
interface CommentItem {
  commentId: number;
  noteId: number;
  userId: number;
  content: string;
  createdAt: number;
  likeCount?: number;
  rootId?: number;       // 根评论ID
  parentId?: number;     // 父评论ID
  floor?: number;        // 楼层号
  replyCount?: number;   // 子回复总数
  state?: number;
  previewReplies?: CommentItem[];  // 前N条子回复
}
```

## 8. 已知限制

1. **评论内容无校验**：`content` 为 null 或空字符串不会被拒绝
2. **点赞计数最终一致**：Redis 计数实时准确，MySQL `like_count` 有 30s 窗口延迟
3. **深分页性能**：`LIMIT/OFFSET` 在数据量大时性能下降，后续应演进为游标分页
4. **无敏感词过滤**：评论发布后无自动审核，需后续接入

## 9. 从 Cassandra 迁移的变化

| 项目 | Cassandra (旧) | MySQL (新) |
|------|---------------|-----------|
| 存储 | 3 张 Cassandra 表 | 3 张 MySQL 表 (索引/内容分离) |
| 评论查询 | `findByNoteId` 扫全表 | `idx_obj_root` 复合索引分页 |
| 嵌套回复 | 不支持 | root_id + parent_id 盖楼 |
| 点赞计数 | Cassandra COUNTER + @Async 直写 | Redis + Kafka → 30s 批量刷 MySQL |
| 内容加载 | 与索引同表，每次全量返回 | 索引分页 → 批量 IN 查内容表 |
| 前端 | 平铺列表 | 嵌套折叠 + 预览回复 + 分页加载 |
