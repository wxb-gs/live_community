# 微服务修复实施与部署

日期：2026-10-22；目录结构于 2026-10-23 整理。当前模块位置见 [项目结构与服务边界](项目结构与服务边界.md)，脚本通过 Maven 自动解析位置。本文描述代码和工具的实际实现，替代旧教程中的启动及调用方式。

## 1. 当前实现

| 领域 | 实施结果 |
| --- | --- |
| 网关 | Reactive Spring Cloud Gateway，经 Nacos 将 HTTP 转发到各业务服务；没有 Dubbo 依赖和业务 Controller |
| 身份 | 网关验证 JWT，业务 HTTP 再次独立验证；忽略请求体中的操作者身份；发布在业务层校验作者 |
| 内部调用 | Dubbo 保留在业务服务之间；公共 Filter 对接口、方法、参数、时间戳和 nonce 做 HMAC 校验并拒绝重放 |
| 发布 | 申请上传 → PUT → 校验实际对象并确认 → 作者发布；确认时按 ETag 条件复制到不可变 ready 对象 |
| 文件 | upload-service 拥有存储配置、元数据、签名及临时文件清理；文件申请时固定 ownerId 和 noteId；内容保存引用 |
| 互动 | MySQL 关系和计数为权威数据；desiredActive 设置状态；requestId 幂等；本地事务更新关系、计数、命令结果和 Outbox |
| 计数投影 | 内容和评论分别消费 interaction_state 的绝对计数及版本；旧版本和重复版本不覆盖 |
| 浏览 | 内容服务通过访问日志和笔记增量的同一事务持久化；X-View-Id 控制单次访问重试，不再依赖 Redis 批量取走 |
| 搜索 | 账号、内容写各自事务 Outbox；search_documents 为唯一正式来源；ES external version 和永久墓碑拒绝旧写入 |
| 数据权限 | 提供独立服务账号创建和表级权限脚本、只读对账及越权查询检查；应用不再默认连接 root |
| 契约 | common-core 与各领域 API 独立 Maven 模块；社区契约合并为 community-api，公开 Java 类型保持兼容；未使用的 common 聚合已移除；契约无 Web starter |
| ID | Leaf 客户端每次预留 64 个 ID，本地缓存；分配失败不生成替代 ID，迁移不重置已有号段高水位 |

内部代码按 content、comment、interaction、access 和 integration 包组织；HTTP/RPC 适配器归入所属领域，跨领域目标可访问性由集成适配器实现。互动写入不引用内容或评论 Repository。

计数状态转换和评论楼层分配显式使用 READ COMMITTED，并在持有目标计数/评论主题行锁后读取当前状态，避免 MySQL 默认快照导致重复计算。计数行采用无变化 UPSERT 获取排他锁，避免 INSERT IGNORE 后再升级锁的并发死锁路径。

同步接口链路：前端 → HTTP Gateway → 业务 HTTP Controller → 本地应用服务。只有跨业务服务的同步通信走 Dubbo。HTTP 和 RPC 适配器复用本地应用服务。

路由：`/api/auth/**` → auth-service；`/api/note/**`、`/api/interaction/**` → note-service；`/api/upload/**` → upload-service；`/api/search/**` → search-service。网关默认连接超时 3 秒、响应超时 10 秒；写请求不配置透明重试；实例级固定窗口限流通过 gateway.requests-per-second 配置，不宣称集群统一配额。

## 2. 与原方案的具体取舍

- 暂不新增独立评论、互动、用户或 Feed 进程。应用接口与数据归属先收敛，互动独立部署仍以扩容或故障隔离证据为前提。
- 浏览量先使用同步数据库事务，代替原方案的异步可靠批次。数据库成功前请求不视为成功；同一 X-View-Id 重试不重复累计。不做独立访客去重。高流量下可再演进为持久日志和批量写入。
- 搜索及计数消费者采取无限退避重试，不默认跳过毒消息，也不自动进入 DLT。日志与消费积压可用于发现问题；修复事件或兼容消费者后再恢复。基础监控平台仍未建设。
- 新文件在申请时固定所属笔记，READY 对象不可覆盖；确认重复调用返回已有结果。避免跨服务事务和二次绑定协议。只自动清理过期临时对象；未引用的 READY 对象不按超时自动删除，以免删掉有效引用。
- 历史笔记的裸 objectKey 由文件服务按 legacy-bucket（默认 notes）解析；不要求一次性改写历史对象。reconcile 工具列出历史引用，缺失对象需实际 MinIO 核对，不能由静态代码证明存在。
- 新版 Leaf 接口含批量取号方法，应先升级 Leaf provider，再升级客户端。Snowflake 和 Leaf 调试 HTTP 默认关闭；启用 Snowflake 前必须另行配置唯一节点身份，不把它作为当前业务发号路径。

## 3. 迁移前准备

1. 保存当前工作区和数据备份。现有评论从 Cassandra 迁移到 MySQL 的工作已保留，并作为本轮内容/互动改造的基础。
2. 停止旧版写入、旧互动消费者、旧浏览结算器，以及向正式索引写入的 Canal 和 Worker。不要同时运行旧 Redis 聚合和新版权威写入。
3. 保留 Redis 快照：旧评论互动关系可能仅存于 Redis；已丢失的用户关系无法靠聚合点赞数恢复。
4. 启动 MySQL、Kafka、Redis、Nacos、MinIO、ES。Docker Compose 的 canal-demo profile 默认不启用；Cassandra 不参与当前服务链路。基础设施脚本不会再等待二者。
5. 为部署设置 JWT_SECRET、RPC_SHARED_SECRET、各服务 DB_USER/DB_PASSWORD 及对象存储凭证；所有业务服务使用相同的内部 RPC 签名密钥。开发默认值仅供本地使用。Dubbo、数据库、对象存储管理端口应限制在可信网络。
6. MinIO endpoint 必须同时可供浏览器和服务访问，配置浏览器 PUT 所需 CORS。不要改写预签名 URL 的主机或路径，修改签名地址不能代替配置正确 endpoint。

本轮未自动执行以下数据库、索引迁移；这些命令会变更部署环境，应在完成备份和停写后按顺序执行。

## 4. 数据库迁移与对账

安装工具依赖：

```powershell
python -m pip install -r scripts/requirements-boundaries.txt
$env:MIGRATION_DB_USER = "root"
$env:MIGRATION_DB_PASSWORD = "<迁移账号密码>"
python scripts/migrate-boundaries.py --maintenance-confirmed --legacy-redis-url redis://localhost:16379/0 --grant-dev-users
python scripts/reconcile-boundaries.py --verify-permissions
```

迁移工具执行增量表/字段创建、BIGINT 计数转换、号段高水位修正、旧 Redis 关系导入、计数重建、旧浏览增量一次性导入，以及账号/内容当前搜索投影 Outbox 回填。不会清空用户表、删除 Redis Key 或重置发号高水位。旧浏览聚合在 note_view 中使用保留的 legacy-view-* 事件 ID 防止重复导入。

DDL 在 MySQL 中可能隐式提交，整个迁移不承诺一次性原子完成。工具通过字段存在性及幂等写入支持停写状态下重跑；重跑会提升投影版本并再次产生当前快照事件。禁止在新版已恢复写入后重新导入旧 Redis 快照。

--grant-dev-users 只针对 auth_app、note_app、upload_app、leaf_app 创建开发账号并收敛其权限。为防止历史宽权限遗留，会撤销这四个应用账号的原有授权，再授予所属表的 SELECT/INSERT/UPDATE/DELETE；不要把其他用途的账号复用为这四个账号。密码采用相应环境变量，未设置时为本地开发默认值。生产账号由部署管理者配置，运行时不授予 DDL。

对账工具输出权威关系/计数差异、内容/评论投影差异、未投递 Outbox 和历史文件引用。旧 Redis 未导入时会明确提示数据缺口；不能把缺失关系自动补成某个真实用户的点赞。权限验证实际执行所属表与非所属表的 SELECT，越权访问未被拒绝就失败。

## 5. 搜索初始化与重建

全新环境先执行：

```bash
bash scripts/init-nacos-config.sh
bash scripts/init-es.sh
```

init-es.sh 为全新 notes_v1/users_v1 建立 notes/users 别名和 IK 映射；已有索引或别名保持不变。不要运行旧版“先删除索引再创建”的初始化命令。

已有具体 notes/users 索引的环境，在所有搜索写入者停止并备份后，先转换为别名：

```powershell
python scripts/init-search-aliases.py --maintenance-confirmed
```

该工具先阻止原索引写入、克隆完整索引并核对数量，再原子移除原名称并将克隆绑定为同名别名。数据保留在 *_legacy_* 克隆中；如果克隆或切换失败，检查原索引的 index.blocks.write 状态后再恢复写入，不要重复删除原数据。

后续全量重建：

```powershell
python scripts/rebuild-search.py --worker-stopped-confirmed
```

此操作只要求正常搜索 Worker 保持停止，业务写入和 Outbox relay 可继续：记录 Kafka 起点 → MySQL 一致性快照写新物理索引 → 追平快照期间消息至屏障位点 → 再检查 Worker 无活动成员 → 原子切换两个别名 → 重启 Worker。未投递 Outbox 随后继续进入新索引。失败时不切换别名；旧物理索引和起止位点保留供回滚与排查。

首次建立 Outbox 后必须重建旧索引，不能把旧 ES 内部版本当成新的领域版本继续覆盖。旧 Worker 必须升级为支持 external version 的新 Worker。生产操作前应在真实 Kafka/ES 环境演练消费者位点、失败恢复和别名切换。

## 6. 构建与启动

先构建前端再打包，保证网关静态资源来自最新 front/dist，而不是旧的 src/main/resources/static 缓存产物：

```powershell
Push-Location front
npm ci
npm run build
Pop-Location
mvn clean verify
mvn install -DskipTests
```

install 会将契约和基础模块安装到本地仓库，便于分模块维护。普通运行可直接用各模块 target 下的可执行 JAR，避免逐模块 spring-boot:run 找不到新契约依赖。

初始化 Nacos 配置后，按 Leaf → Upload → Auth/Note → Search/Worker → Gateway 启动。scripts/start-all.sh 现在先构建最新前端、安装后端产物，再启动 JAR；--no-build 使用已有 JAR。该脚本不自动执行存量数据迁移，应先完成第 4、5 节。开发页面仍可通过 Vite 5173 访问，生产包通过网关静态资源提供页面。

## 8. 故障处理与回滚

- Outbox 发送失败：数据库行保留，relay 后续重试；检查 sent_at IS NULL 的数量和最老 created_at。不能通过删除待发送行消除积压。
- 投影消费失败：分区保留失败消息并持续重试；先修复依赖或事件兼容性，再恢复消费。不能直接跳过造成未解释的数据缺口。
- 对账不一致：先停止相关写入，保留差异报告，确认是否尚有积压；不要在活跃写入时用旧 Redis 覆盖新权威关系。
- 搜索回滚：旧物理索引仍在，但切换后的新事件未必在旧索引；停止 Worker、追平所需事件，再切换别名及重启，不能只切别名假设零丢失。
- 数据库回滚：保留新增字段和表，通过兼容应用回退；恢复旧权威链路前必须停写、排空新版事件并对账，禁止双路径并行计数。不得回退到越权发布或上传确认前即发布的行为。
- 临时文件清理只删除过期 pending 对象；READY 文件不基于猜测的超时清理。已有数据和备份不自动删除。
